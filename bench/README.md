# Benchmarks

jz is measured the way a pipeline runs it, one process per call from start
to exit, with [himorime](https://github.com/nao1215/himorime). himorime
builds jz, runs each command in interleaved rounds, and reports latency,
CPU time, peak RSS and, for the large inputs, throughput.

```console
$ go install github.com/nao1215/himorime@latest
$ make bench            # himorime run bench
$ make bench-compare    # himorime compare --against main bench
$ make bench-docs       # jz against jc and jo, written into website/content/compare.md
```

## Regression suite: himorime.yaml

`make bench-compare` checks main out into a temporary Git worktree, builds
it and your working tree, and measures both in the same rounds, so a
background job slows both revisions instead of one. `BASE=v0.7.1 make
bench-compare` compares against another revision. `himorime run --filter
'ps 100k' bench` measures one benchmark.

On a pull request, `.github/workflows/bench.yml` runs `himorime ci bench`
the same way, with the base of the pull request as the base, on one
runner. The job fails when a command is slower, uses more CPU time or more
memory than the base beyond the tolerance in `himorime.yaml` with 95%
confidence. A difference too close to call is reported as inconclusive and
does not fail the job. The comparison is on the job summary page and the
JSON report is kept as an artifact.

The inputs are generated by `gen.sh` before measuring, so no fixture is
committed, and both revisions run the working tree's `gen.sh`.

| Benchmark | Commands | Measures |
|-----------|----------|----------|
| `version` | `jz version` | starting jz, with no registry loaded |
| `detect df` | `jz`, `jz --parser df`, `jz --parser df --variant gnu` on ten rows | detecting the format among every built-in definition, reading only the definitions of df (also what `jz run df` does), and one named definition |
| `detect nothing` | `jz` on text no definition reads | the worst case of detection, every candidate rejected, exit 4 |
| `registry size` | `jz` with 26, 500 and 1000 extra definitions in `JSONIZE_REGISTRY_PATH`; `jz --define` | how loading and detection grow with a registry, and a definition given inline |
| `ps 100k rows` | detected, `--parser ps`, with `-p`, with `--stream` | an eleven-column whitespace table read whole, indented and record by record |
| `df 100k rows` | `jz --parser df` | a table aligned under its header |
| `mount 100k lines` | `jz --parser mount` | lines read with a regular expression and a field split into an array |
| `env 100k lines` | `jz --parser env` | KEY=VALUE lines |
| `data formats 100k records` | `--format` csv, tsv, ltsv, json, jsonl, yaml, lines, nul | each data format, read from a file |
| `csv 100k rows` | `--type`, `--extract`, `--exclude`, `--stream` | one CSV read typed, narrowed by key and streamed |
| `jsonl 100k records` | `--format jsonl`, with `--stream` | JSON Lines from standard input, read whole and passed through |
| `jz new` | arguments, `--path`, `--each` over 100 000 records | building an object from arguments, a nested object, and fixed values attached to each record of a stream |

Numbers from different machines are not comparable; compare revisions on
one machine, as `make bench-compare` and CI do. Peak RSS shows what a
command holds: `--stream` rows hold a fraction of what the whole-document
rows do.

## Comparison suite: compare/himorime.yaml

`compare/himorime.yaml` measures jz against jc and jo on the same input:
`df -h` and `ps aux` of the machine it runs on (the table repeated to
100 000 rows), a generated CSV of 100 000 rows, and objects built from
arguments. Every case is measured with every core and pinned to one core
with `taskset`. Before measuring, a setup step checks that both tools
return the same number of records, or the same JSON for jo.

It is not a CI gate. `make bench-docs` needs jc, jo, jq and taskset
(Linux), runs the suite, and replaces what is between the
`himorime:begin benchmarks` and `himorime:end benchmarks` markers in
`website/content/compare.md`. The environment and tool versions printed
under the tables come from the same run.
